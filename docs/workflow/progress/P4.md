# P4 progress: recording studio

## 2026-10-07: first recording path

- Capture adapter (`packages/recorder`): FFmpeg display and microphone capture into FFV1 `bgr0` and 16-bit PCM at 48 kHz, constant 30 fps, exact sample alignment to the first video frame, pause/resume segments joined without re-encoding, `session.json` evidence.
- Main service (`apps/desktop/src/recording.ts`) and `recording:*` IPC with opaque device ids; Linux X11 and Windows displays from Electron in physical pixels; PulseAudio and DirectShow microphones; Wayland and macOS report an unavailable message.
- New recording dialog: screen cards, microphone menu, countdown (cancellable), elapsed time, Pause/Resume, Stop, missed-frame line. Stop names the take by date, imports it and opens a project; working media is removed and `session.json` kept.
- Preview: recordings use the exact native RGB still path.

Findings: lavfi test sources ignore `-re`, so FFmpeg dropped thousands of generated frames and the dialog showed a bogus missed-frame count; the synthetic sources now use `realtime`/`arealtime`. The still-frame command forbids implicit conversion, so `bgr0` needed an explicit `scale,format=bgra`, verified exact against an unconverted decode. One media-test run failed once while three native tests loaded the CPU and could not be reproduced in four reruns; the drop assertions are now sanity bounds instead of zero.

Evidence: media tests above, packaged `tests/native/recording.test.ts` in the cloud VM with synthetic devices. Not claimed: real screen or microphone hardware, Windows or macOS runs, playback of recorded projects (FFV1 needs proxies), window/region, system audio, camera, recovery, shortcuts, scenes and takes, pointer telemetry.
