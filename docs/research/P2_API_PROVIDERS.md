# P2 API-provider contract notes

Checked 2026-09-19 against primary provider and Electron documentation. An isolated packaged native OpenAI model-list call authenticated successfully; its paid edit attempt later returned HTTP 429. A separate authenticated DeepSeek fixture edit passed on 2026-09-20.

- [OpenAI lists models](https://platform.openai.com/docs/api-reference/models/object?lang=curl) at `GET https://api.openai.com/v1/models`. Its basic model object identifies a model; presence alone does not prove that the model accepts the editor's proposed request or tool format.
- The editor intersects OpenAI's live IDs with the documented [GPT-4.1](https://developers.openai.com/api/docs/models/gpt-4.1) and [GPT-4o](https://developers.openai.com/api/docs/models/gpt-4o) text model families and dated snapshots. Both document Chat Completions and function calling. This conservative subset excludes base, embedding, audio, realtime, image, and newer reasoning models until their exact request contracts are reviewed and tested. Live catalog membership still determines what the account may select.
- [DeepSeek lists models](https://api-docs.deepseek.com/api/list-models/) at `GET /models` on its [documented `https://api.deepseek.com` base](https://api-docs.deepseek.com/). The returned model ID/owner likewise does not establish editing capabilities.
- The initial DeepSeek chooser intersects the returned IDs with the documented chat/reasoner, Flash, and V4 Flash/Pro names from its [model-list example](https://api-docs.deepseek.com/api/list-models/) and [V4 change log](https://api-docs.deepseek.com/updates/). Unknown model families remain hidden until the adapter and tests support them.
- [DeepSeek's Responses compatibility table](https://api-docs.deepseek.com/guides/responses_api/) is narrower than OpenAI's contract. It documents unsupported stateful conversation parameters and built-in tools, and warns that some unsupported parameters are silently ignored. Do not reuse Codex App Server thread/skill/MCP/subagent semantics or infer support from a successful HTTP status. Validate only the fields and tools the selected provider actually supports, with provider-specific tests.
- [Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage) is main-process storage backed by platform facilities when available. Its documentation warns that Linux `basic_text` can use a hardcoded plaintext password. Never treat that backend as protected persistence; use session-only key memory or a clear failure if a secure backend is unavailable. Verify the selected backend and restart behavior in the isolated packaged native environment.

The provider adapters must pin destinations in main, bound and redact errors, separate model-discovery reads from user-started generation, and pass only validated edit intent to the shared transaction engine. Actual credentials, provider response content and account limits remain private. Recheck these external contracts when implementing P2-08 through P2-10 because endpoints and capability tables can change.

The packaged native draft fixture now substitutes `fetch` only in Electron main after app startup, with the production adapter resolving the main transport at call time. Separate OpenAI and DeepSeek runs constrain the shim to the selected provider's fixed model and Chat Completions URLs and a synthetic test key. The actual native UI and guarded transaction service then commit a trim, reject an obsolete head, undo the commit, redact a provider failure and reopen the project without changing source/baseline bytes. This proves both packaged provider routes with deterministic responses, not provider authentication, real model compliance or billing behavior.

The protected key file now contains a versioned encrypted envelope with the key and optional selected model. A prior ciphertext containing only the key remains readable and migrates when the user selects a model. Replacement writes a fresh envelope without the previous selection; session-only connect removes the ciphertext. Reopen restores a saved model only after fresh provider model discovery confirms it is still supported. This is an internal format change, not a provider API claim. Fake secure-storage unit tests cover the migration, restart, replacement and failure boundary. The ordinary Linux guest offered only the insecure `basic_text` backend; a separate isolated guest with real GNOME Secret Service and the packaged app passed `gnome_libsecret` protected OpenAI key/model reopen, fresh catalog revalidation, empty renderer key field and explicit removal. This does not prove another OS backend, DeepSeek or a paid edit.

## Gemini API expansion, 2026-09-20

ADR 0015 fixes a third main-owned API-key route at Google's [OpenAI-compatible models and Chat Completions endpoints](https://ai.google.dev/gemini-api/docs/openai). The live model IDs are intersected with reviewed stable text/function models from the [official model list](https://ai.google.dev/gemini-api/docs/models); membership alone does not establish accepted generation or tool-loop behavior. The adapter sends a fixed client-identification header under Google's [partner guidance](https://ai.google.dev/gemini-api/docs/partner-integration). The [Gemini 3 thought-signature contract](https://ai.google.dev/gemini-api/docs/generate-content/thought-signatures) requires the first function call's opaque signature on its matching assistant replay; parallel assistant calls precede their tool results. The editor bounds and validates those signatures, holds them only in main's current turn memory, and leaves them out of renderer and persisted conversation. The completion-token parameter and this full tool loop remain unverified against a live Gemini account.

Unit tests cover the pinned destinations, no redirects, key separation/redaction, catalog filtering, malformed and cross-provider signature rejection, exact transient replay and shared guarded edit intent. The packaged isolated Linux Settings fixture passed disconnected/rejected-key Gemini state. A main-only synthetic Gemini 3.1 Flash-Lite native fixture passed committed trim, preview, stale rejection, shared Undo, error redaction, immutable source/baseline, reopen and exact signature replay, with guest-only visual inspection of the real Electron window. The same package passed OpenAI and DeepSeek synthetic regression flows. No authorized Gemini credential, authenticated model discovery, paid completion or real thought-signature replay was available; these remain P2 gates.
